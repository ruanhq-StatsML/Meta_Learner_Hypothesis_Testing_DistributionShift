\begin{abstract}
This consolidated English PO prioritizes two \textbf{production-practical} agent patterns validated in-repo: \textbf{ReAct} (thought$\rightarrow$action$\rightarrow$observation loops with tool drift) and \textbf{multi-agent debate} (pro/con/judge with optional round early-stop).
Both use the same FSDS spine---REF/LIVE batches on $X$, segment embeddings $Z$ for budgets, and \texttt{impact\_receipt} for finance---and show \textbf{31--39\%} variable cost reductions in Monte Carlo while preserving or improving task success on multi-agent runs.
The document includes the full uplift/federated portfolio (Tables R1--R6), all collaboration MC scenarios (R7--R9), and elaborated ReAct/multi-agent result tables (R10--R10b).
A single-file build is \texttt{fsds\_full\_scenarios\_po\_en\_monolithic.tex}.
\end{abstract}

\section{Executive summary: why ReAct and multi-agent first}

\paragraph{ReAct is the default production shape.}
Most tool-using copilots already emit a ReAct-shaped trace: an internal \emph{thought}, an \emph{action}/tool call, and an \emph{observation} (API payload, retrieval snippet, error string).
When the environment shifts---noisier tools, new API version, bad retrieval---uniform token budgets waste spend re-expanding stable segments.
FSDS localizes shift on $X$ and reallocates $L$, tier, and checks on $Z$ \textbf{per segment}, which is why ReAct is the most \emph{deployable} pattern in this repo (Table~\ref{tab:practical-react-ma}).

\paragraph{Multi-agent adds measurable collaboration leverage.}
Pro, con, and judge (or reviewer/critic/arbiter) share one monitor window but distinct embeddings $Z_b$.
LIVE drift on \texttt{con} mimifies adversarial or off-policy opponents; FSDS down-tiers the drifting role while keeping judge budget on the critical path---\textbf{37--39\%} \$/debate in MC plus \textbf{+2pp} success in the dedicated 50-episode artifact (Table~\ref{tab:ma-roles}).
Stacking \texttt{debate\_early\_stop\_round} adds macro savings when round centroids stabilize (Table~\ref{tab:stacked-ma}).

\paragraph{Incremental value rule (all tracks).}
Diagnostics (MMD, domain AUC, overlap) \emph{gate}; dollars attach when \texttt{fit\_agent\_plan} budgets execute and receipts log \texttt{rule\_ids}.

\section{Embedding logic (requirements for ReAct and multi-agent)}
\label{sec:embedding}
FSDS uses \textbf{two layers}: segment matrix $Z\in\mathbb{R}^{B\times d}$ (per thought/action/obs or pro/con/judge) for \emph{within-episode} budgets, and episode vectors $X=\texttt{trace\_features}$ stacked into REF/LIVE batches for \emph{between-window} MMD/domain AUC.
Rows of $Z$ are L2-normalized; $\texttt{trace\_features}=\mathrm{concat}(\mathrm{mean}(Z),\ \text{scalars})$.
Multi-agent early-stop uses a separate tensor $(R,B,d)$ over debate rounds---not the same as budgeting $Z$.
Full specification: \texttt{fsds\_embedding\_logic\_en.tex}, \texttt{fsds\_embedding\_mapping\_mmd\_en.tex} (mapping tables + MMD/shift equations); Chinese: \texttt{fsds\_embedding\_mapping\_mmd\_zh.tex}.

\label{sec:react-practical}

\begin{itemize}[nosep]
  \item \textbf{Surface:} any agent loop with distinct phases (copilot, support bot, internal ops ReAct).
  \item \textbf{Code:} \texttt{build\_react\_trace} $\rightarrow$ \texttt{fit\_agent\_plan} (\texttt{fsds\_sot/applications.py}); demo \texttt{demo\_fsds\_react\_agent.py}; MC row \texttt{react\_observation\_drift} in collaboration suite.
\end{itemize}

\subsection{Objects $(X,Y,Z,W)$}
\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Object & ReAct instantiation \\
\midrule
$Z$ & Three segment embeddings: thought, action, observation ($3\times d$) \\
$X$ & \texttt{trace\_features} = mean($Z$) $\oplus$ scalars (segment count, tool quality stats) \\
$W$ & REF batch of traces vs LIVE batch (rolling windows, e.g.\ last 7d vs prior 7d) \\
$Y$ & Task success / resolution (for MC and optional outcome monitoring; not RF label for $W$) \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Mechanism (why it saves money without hurting success)}
Uniform SoT assigns each segment the same expansion budget (demo: 480 tokens/segment, 2 checks $\times$ 3 segments = 6 checks).
When \textbf{observation} drifts but thought remains stable, FSDS:
\begin{enumerate}[nosep]
  \item detects batch shift on $X$ (REF vs LIVE);
  \item assigns higher \texttt{shift\_score} to the observation segment in $Z$;
  \item increases checks/tier on observation \textbf{only}, trims thought/action $L$.
\end{enumerate}
Collaboration is \textbf{sequential}: segments share one topology decision but receive \textbf{different} budgets---not a global 10\% token cut.

\subsection{Measured increment (repository)}
From collaboration suite MC ($n{=}24$ eval, batch 28): mean cost \textbf{\$0.02064 $\rightarrow$ \$0.01416}/episode (\textbf{31.4\%}), checks \textbf{6 $\rightarrow$ 3}, tokens \textbf{1440 $\rightarrow$ 1310}, success held at $\sim$0.71 (Table~\ref{tab:practical-react-ma}).
Unit save $\sim$\textbf{\$0.0065}/episode $\times$ traffic tier annualizes via \texttt{config/fsds\_economics\_assumptions.json}.

\subsection{Production wiring (checklist)}
\begin{enumerate}
  \item \textbf{Log} per step: \texttt{\{phase, embedding, tool\_ok, latency\}}; append to REF/LIVE store by calendar window.
  \item \textbf{Sidecar} (hourly/daily): stack \texttt{trace\_features}, run \texttt{fit\_agent\_plan}, emit \texttt{suggest\_intervention(..., attach\_impact\_receipt=True)}.
  \item \textbf{Scheduler} applies \texttt{intervention.budgets} per phase (cap thought tokens, add verifier on observation).
  \item \textbf{FinOps} reconciles API invoice delta to receipt \texttt{estimated\_net\_gain\_usd} (\texttt{bank\_cash\_bridge.py}).
\end{enumerate}

\paragraph{Playbook (in-repo).}
\textit{``Budget Observation vs Thought; re-tool if obs shift without tool\_ok.''} --- \texttt{pattern\_playbook()[REACT]}.

\subsection{Where FSDS runs}

\subsection{Objects and collaboration}
\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Object & Multi-agent instantiation \\
\midrule
$Z$ & Role embeddings: pro, con, judge ($3\times d$) \\
$X$ & Episode \texttt{trace\_features} batched for REF/LIVE attribution \\
$W$ & REF vs LIVE debate windows (opponent/channel drift) \\
$Y$ & Debate success / verdict quality (MC; +2pp in 50-ep artifact) \\
\bottomrule
\end{tabular}
\end{center}
\textbf{Collaboration} = three policies under one FSDS plan: roles \emph{compete} in content but \emph{cooperate} under a shared token envelope and monitor.

\subsection{Per-role incremental budgets (why it beats uniform swarm)}
Table~\ref{tab:ma-roles} shows an example plan under con drift: \texttt{con} at \textbf{287} tokens / \texttt{small} tier vs \texttt{judge} at \textbf{480} / \texttt{medium} on the critical path.
Uniform swarm pays full price for every role every round; FSDS pays for \textbf{shift} where it matters.

\subsection{Measured increments}
\begin{itemize}[nosep]
  \item Collaboration suite: \textbf{37.8\%} cost reduction, \$0.02064 $\rightarrow$ \$0.01283/debate, $-$3 checks (Table~\ref{tab:practical-react-ma}).
  \item Dedicated MC ($n{=}50$): \textbf{39.3\%} cost reduction; success \textbf{0.66 $\rightarrow$ 0.68} (+2pp); artifact \texttt{multi\_agent\_fsds\_economics.json}.
  \item \textbf{Stacked:} micro role FSDS + macro early-stop at round 4/5 (Table~\ref{tab:stacked-ma}) --- use separate receipt tags for finance.
\end{itemize}

\subsection{Production wiring (checklist)}
\begin{enumerate}
  \item Log \textbf{round $\times$ role} embeddings $(R,B,d)$ for early-stop; final-round $Z$ for FSDS budgets.
  \item Run \texttt{debate\_early\_stop\_round} before scheduling round $r{+}1$.
  \item Run \texttt{fit\_agent\_plan} on LIVE-shifted traces; apply per-role \texttt{BranchBudget}.
  \item Attach \texttt{build\_agent\_impact\_receipt} with \texttt{pattern=multi\_agent\_debate}.
\end{enumerate}
